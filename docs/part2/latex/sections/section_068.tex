Each SSD occurrence has its own operation sequence. Actor \ensuremath{\rightarrow} actual blueprint module \ensuremath{\rightarrow} controller \ensuremath{\rightarrow} domain / typed value; UC-01 also uses the local simulator. No DAO/SQL lifeline is present. Synchronous calls use closed filled arrowheads; dashed open arrows carry results. Actual \texttt{alt}, \texttt{opt} and \texttt{break} rectangles enclose the messages they govern, including self-call paths. Inside an outcome \texttt{alt}, separately guarded regions have mutually exclusive conditions. Denial breaks terminate the current interaction; a continuation retains the same request and lifelines. Successful mutation results follow all atomic saves and COMMIT, whose DAO details remain in 4.3.2. Attribute/property reads are notes. Implicit dataclass \guillemotleft{}create\guillemotright{} is not a business operation. Persistence is loaded/saved through data access --- see 4.3.2.

Checkout uses Parts A--E: token replay/denial breaks; quote and fingerprint/T validation; optional ONLINE authorization with a decline break; creation only for COD or approved ONLINE; then exclusive commit success versus rollback. Only the failed branch can release an obtained ONLINE reference. The success branch retains authorization. requestQuote uses Parts A--C: eligibility/distance, Quote initialization, then optional voucher validation/discount and fingerprint. Invalid voucher terminates before discount or a quote result. cancelOrder Parts A/B return \texttt{cancelledOrderAndAmounts} only after successful atomic save and COMMIT; the rollback reply remains separate.
