\textbf{Boundary adapters and guarantees}

\texttt{uid()} always comes from the active server session; posted identity is never accepted. Form adapters retain SSD names while converting camelCase fields to Python keys: \texttt{address} \ensuremath{\rightarrow} \texttt{address\_\allowbreak{}text}, \texttt{baseDeliveryFee} \ensuremath{\rightarrow} \texttt{base\_\allowbreak{}delivery\_\allowbreak{}fee}, \texttt{capacity} \ensuremath{\rightarrow} \texttt{max\_\allowbreak{}active\_\allowbreak{}orders}; \texttt{brandId} \ensuremath{\rightarrow} \texttt{brand\_\allowbreak{}id}. Optional parameters map omitted values to the target defaults. Availability is validated as a boolean. Request.form values are strings; controllers parse and validate them.

OP-25 is the C0 design gap (final status in Table P4-1) \texttt{list\_\allowbreak{}catalogue} wrapper, composing \texttt{catalogue}, the retained-hub read and optional \texttt{hub\_\allowbreak{}menu}; it returns Brand/MenuItem/Hub/HubMenuItem data without adding another SSD operation. The three SSD occurrences remain distinct. OP-43 passes initial \texttt{available} into \texttt{list\_\allowbreak{}item\_\allowbreak{}at\_\allowbreak{}hub} and \texttt{MenuDAO.\allowbreak{}add\_\allowbreak{}listing} in the same insert (P2-S15). OP-41 uses \texttt{brandId} only as current-parent context; \texttt{update\_\allowbreak{}item} pins \texttt{current.\allowbreak{}brand\_\allowbreak{}id}, with no reparent/restore. Snapshot OrderLine data is outside every catalogue mutation. A None controller result for listing commands is adapted to a successful acknowledgement called \texttt{savedRecord} at the SSD boundary.

Mutation success is acknowledged only after commit. The P2-S13/P3-S03 targets require rowcount/guard checks and controlled busy or commit-error rollback; the Section III figures intentionally hide DAO/SQL behind the persistence note and Section 4.3.2. Draft validation maxima/coordinate windows remain draft constraints (P2-S17), not newly locked BRs.
