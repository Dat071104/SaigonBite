Each SSD occurrence has its own operation sequence. Actor \ensuremath{\rightarrow} actual blueprint module \ensuremath{\rightarrow} controller \ensuremath{\rightarrow} domain / typed value. The UC-01 local simulator is described separately. No DAO/SQL lifeline is present. Synchronous calls use closed filled arrowheads; dashed open arrows carry results. Actual \texttt{alt}, \texttt{opt} and \texttt{break} rectangles enclose the messages they govern, including self-call paths. Inside an outcome \texttt{alt}, separately guarded regions have mutually exclusive conditions. Denial breaks terminate the current interaction; a continuation retains the same request and lifelines. Successful mutation results follow all atomic saves and COMMIT, whose DAO details remain in 4.3.2. Attribute/property reads are notes. Implicit dataclass \guillemotleft{}create\guillemotright{} is not a business operation. Persistence is loaded/saved through data access --- see 4.3.2.

acceptReplacement Parts A--C preserve stale refusal before mutation, then exclusive invalid-target withdrawal versus valid-target replacement. Invalid-target outcome returns only a committed withdrawal/reason or controlled failure; it never executes replace\_line. Only the valid-target continuation can return acceptedOrderAndAmounts after successful atomic save and COMMIT. rejectOrder and declineReplacement Parts A/B now return \texttt{rejectedOrder} and \texttt{rejectedOrderAndAmounts}, respectively, inside the committed branch; failed saves return refusal/controlledFailure with rollback. No result implies implementation or a measured transaction guarantee.
