The test plan checks postconditions at three levels: automated unit and postcondition tests on a local database, browser integration across roles, and checks against the deployed VM. Entry requires the intended revision, a fresh or isolated database where applicable, and available test tools. Exit for the automated run requires the recorded suite to complete without failures; the browser and deployed checks require their own recorded steps. A passing suite alone does not establish that every workflow was demonstrated.

At \texttt{252ada1}, the 27 October 2026 local JUnit report records 928 passing test cases. The P5 local browser walkthrough records 60 of 60 passing steps, and the adapted P6 deployed scenarios record 22 of 22 passing steps; their environments and limitations are described in 4.3.6 and 5.2. The P7 entry rerun at \texttt{97574bd} recorded 928 passing tests on 28 October.

The table maps every one of the 30 main-use-case postconditions and minimal guarantees to its recorded test nodes. The actual result is a passing node in the JUnit report; the assertions linked in the coverage register qualify the check. The full node list and reconciliation are in \texttt{docs/part2/test\_report/p7\_2026-10-28/test\_cases.csv}.
